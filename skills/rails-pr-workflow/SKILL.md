# Rails PR Workflow

Use this for Rails branch, commit, PR, CI, and publication work.

Read:

- `../../core/references/rails-pr-workflow.md`
- The target repo's PR template
- `../../docs/voice.md` or a selected profile when drafting text

Defaults:

- Do not use agent/tool branch prefixes.
- Use ticket branches when a ticket exists.
- Use Conventional Commits when no ticket exists.
- Use `gh` for GitHub PR and CI context when available.
- Include validation evidence.
- Keep PR descriptions self-contained.
